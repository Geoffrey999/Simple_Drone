# 黑匣子（W25Q128）使用说明

## 硬件连接

| 信号 | 引脚 | 说明 |
|---|---|---|
| NSS  | PA15 | 软件片选，低有效 |
| SCK  | PC10 | SPI3 |
| MISO | PC11 | SPI3 |
| MOSI | PC12 | SPI3 |
| 指令/取数 | USART3 (PB10=TX, PB11=RX) | **默认 460800 8N1**，与 `printf` 共用 |

> ⚠ USART3 现在由黑匣子独占。`fputc`（printf 输出）在黑匣子倾倒数据期间会被静默丢弃，
> 避免把调试文本混进二进制流里。若还需要 printf，建议改用 USART1 之外的其它空闲串口。
>
> 波特率依据：USART3 挂在 APB1 = 42MHz，460800 在 16 倍过采样下
> `USARTDIV = 42e6/(16×460800) = 5.6962 -> 5+11/16`，实际 461538 Bd，偏差 **+0.16%**
> （UART 单边容限约 2~3%，安全）。16MB 全片倾倒约 **6 分钟**。
> 若 PC 端串口芯片不支持 460800，可在固件里用 `BB:BAUD:115200` 临时降速。

## 记录行为

- **只在解锁（`arm == 2000`）时记录**，未解锁完全不写 Flash。
- 采样频率 **1000Hz**，数据帧固定 **32 字节**。
- Flash 按 4KB 扇区组成**环形缓冲**，写满自动回到 0 号扇区重新擦写，
  因此永远保留**最近约 8.2 分钟**的飞行数据（491520 帧）。
- 每次解锁会切到一个新扇区开始记录，所以一次飞行 = 一段连续序号的数据。
- 每 64 帧插一帧**诊断帧**，额外记录姿态解算内部量（`accel_confidence`、实测解算周期）。
- 固件里有一块 **1024 帧（约 1 秒）的 RAM 环形缓冲**，用来吸收"Logger 正在写 Flash /
  擦扇区"期间新产生的帧。`python bb.py status` 会打印它的**历史最高水位 `hwm`**：
  稳态应该只有个位数~几十帧（换扇区擦除时会短时上涨），**接近 1024 就说明 Logger
  已经跟不上 Flash，丢帧马上开始**。调大采样率/加帧之后先看这个数。

### 帧格式（32 字节，小端）

| 偏移 | 类型 | 字段 | 缩放 |
|---|---|---|---|
| 0 | u16 | magic = 0x4246 ('BF') | — |
| 2 | u8  | type（1=数据帧 2=诊断帧 3=摇杆帧 4=高度帧） | — |
| 3 | u8  | flags（数据帧：bit0 高度有效, bit1 定高模式, bit2 混控被抗饱和缩放, bit3-5 降落断电原因：0=无 1=贴地高度 2=垂速塌陷 3=超时 4=气压门控升级 5=加计冲击；高度帧另有一套，见下） | — |
| 4 | u16 | seq（数据帧是 1kHz 序号；诊断帧低字节=conf档位, 高字节=周期/100µs） | 无符号 |
| 6 | i16 | roll | ×100 ° |
| 8 | i16 | pitch | ×100 ° |
| 10 | i16 | yaw | ×100 ° |
| 12 | i16 | gyro_x | ×10 °/s |
| 14 | i16 | gyro_y | ×10 °/s |
| 16 | i16 | gyro_z | ×10 °/s |
| 18 | i16 | accel_x | ×1000 g |
| 20 | i16 | accel_y | ×1000 g |
| 22 | i16 | accel_z | ×1000 g |
| 24 | u32 | 四路电机各 7bit（0..127）+ 油门 4bit（0..15） | ×(4200/127)、×(4200/15) |
| 28 | u8  | 电量 % | — |
| 29 | u8  | reserved（摇杆帧=0xB7，高度帧=0xC3，其余 0） | — |
| 30..31 | — | ARM ABI 填充（不属于任何字段） | — |

### 高度帧（type=4，50Hz，与气压样本同频）

同一个 32 字节结构，按 type 区分槽位含义；`seq` 借用当前数据帧的序号
（**不递增**），上位机靠 type 把它排除在序号时间轴之外。占约 5% 空间。

| 槽位 | 内容 | 缩放 |
|---|---|---|
| roll | 气压高度（融合器输入） | ×0.01 m |
| pitch | 融合高度 | ×0.01 m |
| yaw | 垂直速度 | ×0.01 m/s |
| gyro_x | 创新 innov = baro−alt | ×0.0001 m |
| gyro_y | 加计偏置估计 | ×0.0001 m/s² |
| gyro_z | 气压更新间隔 baro_dt | ×0.1 ms |
| accel_x | 地面参考面 alt_ref | ×0.01 m |
| accel_y | 原始气压（**固件里是 Pa**，按 10 Pa 一档存） | ×10 Pa（解码后换算成 hPa 显示） |
| accel_z | 定高油门修正量 | ×1 PWM |
| motors | 低 16 位 = 定高基准油门（学到的悬停油门），bit31 = hover_valid | ×1 PWM |
| flags | bit0 baro_ok, bit1 创新被限幅, bit2 增益参数被拒, bit3 气压值有效 | — |

> 为什么要有它：判断高度算得对不对，必须同时看到"输入(baro) / 输出(alt,vel) /
> 修正量(innov,bias)"三组量。只记输出永远分不清是气压计坏了还是滤波器坏了。
> Python 侧用 `log.alt_fused` / `log.alt_baro` / `log.alt_vvel` 直接取。

> 固件侧权威定义见 [`Core/Inc/blackbox.h`](../Core/Inc/blackbox.h)，
> 上位机侧见 [`bb_format.py`](bb_format.py)。**改任意一侧都必须同步另一侧**，
> 改完跑一次 `python bb.py selftest` 即可确认两边是否还对得上。

### Flash 布局

```
每个 4KB 扇区：
  [0x000 .. 0x0FF]  扇区索引头（32 字节有效 + 填充，保证数据从 256 对齐处开始）
  [0x100 .. 0xFFF]  3840 字节数据 = 15 页 × 256 字节 = 120 帧 × 32 字节
```

> 数据区必须从 256 字节整数倍地址开始：W25Q128 的页写入不能跨页边界（会回卷）。

## 上位机命令

```bash
# 依赖（串口和绘图功能需要，离线解析不需要）
pip install pyserial matplotlib

cd tools

# 列出串口
python bb.py ports

# 连通性 / 状态查询
python bb.py ping   --port COM3
python bb.py status --port COM3

# 扫描扇区索引头（看看录了几段）
python bb.py scan --port COM3

# 全片擦除（约 200 秒，必须处于未解锁状态）
python bb.py erase --port COM3

# 把整片 16MB 拉到本地（必须处于未解锁状态）
python bb.py dump --port COM3 -o flash.bin

# 离线分析：打印判读报告 + 出图 + 导出 CSV
python bb.py analyze flash.bin --plot --csv flight.csv
#   --plot 会出两张图：
#     blackbox_plot.png       第 2 张是【设定值(虚线) vs 实测(实线)】；
#                             有高度帧时末尾再多 2 张（气压vs融合高度、垂速+定高修正量）
#     blackbox_plot_step.png  每个阶跃对齐到 t=0 叠图（调 PID 直接看这张）

# 阶跃 / 回正响应（调 PID 用）：算上升时间、超调、稳定时间、一阶 tau
python bb.py step flash.bin                    # roll 和 pitch 都分析
python bb.py step flash.bin --axis roll --csv step.csv

# 让固件注入方波做精确阶跃测试（需已解锁 + 摇杆回中）
python bb.py stepgo --port COM3 --axis roll --amp 8 --period 2048 --cycles 4
python bb.py stepgo --port COM3 --off          # 取消

# # 格式环回自检（不接硬件）
python bb.py selftest

# 参数（内部 Flash 模拟 EEPROM）
python bb.py cfg info                          # 参数从哪来 / 有没有未生效的改动
python bb.py cfg list                          # 75 项参数（* = 改过但没重启）
python bb.py cfg set pid.roll_inner.kp 12 --save --reboot
python bb.py cfg hist 5                        # 最近 5 次保存 + 每版改了什么
python bb.py preset apply presets/example_soft.json --save --reboot

# 图形界面（调参面板，等价于上面那些命令）
python bb_gui.py
```

### 阶跃响应测试的正确做法

`analyze` 回答"为什么偏飞"，`step` 回答"PID 该怎么调"。后者需要**专门飞一次**：

0. **地面上**（未解锁）发命令：
   `python bb.py stepgo --port COM3 --axis roll --amp 8 --period 2048 --cycles 4`
   它进入“待触发”状态，**不会立即开始**
1. 正常起飞，悬停稳定（摇杆回中、油门 >=1300、倾角 <12°）
2. 满足上面条件**持续 0.5 秒**后，固件自动开始注入 ±8° 方波
   —— **全程不需要连串口**；期间不要碰摇杆（一碰就取消）
3. 等它自己飞完 8 秒，降落、上锁
4. `python bb.py dump --port COM3 -o f_step.bin`
5. `python bb.py step f_step.bin --axis roll`

**为什么周期要 ≥1600ms**：上位机要求设定值在新值上保持 ≥800ms 才认作真阶跃
（更短的就是"点动"，终值必然回落到 0，算不出超调和稳态误差）。推荐
`--period 2048`，半周期 1024ms 正好是摇杆帧间隔 32ms 的整数倍，边沿无误差。

**安全设计**：注入需同时满足已解锁、油门 >=1300、姿态倾角 <12°、摇杆回中，
且持续 0.5 秒才开始；摇杆偏离中位 >40 立即取消；幅度上限 25°、周期上限 4000ms、
次数上限 10；命令 120 秒内未被触发则自动作废（不会到下次飞行才突然发作）。

**回正分析**只统计"摇杆回中、飞机自己往回扳"的那段。想测它，要**真的松手**
让飞机自由回正，否则测不到。

格式环回自检（不接硬件，确认固件与上位机格式一致）
python bb.py selftest

### 串口协议（固件侧）

| 指令 | 作用 |
|---|---|
| `BB:PING` | 回 `BB:OK` |
| `BB:STAT` | 回一行状态：是否识别到 Flash、当前扇区、已记录/丢帧数 |
| `BB:SCAN` | 逐条列出有效扇区索引头 |
| `BB:ERASE` | 全片擦除（后台执行约 200s，仅未解锁时受理） |
| `BB:DUMP` | 先回 `BB:DUMP start=0 bytes=16777216`，随后原样发送 16MB 镜像，最后回 `BB:DUMPEND` |
| `BB:CAL` | 回 `BB:CAL`（陀螺上电标定质量）、`BB:GYRO`（当前残余）、`BB:ACC`（加计倾角） |
| `BB:STEP <roll\|pitch> <amp> <period_ms> <cycles>` | 向目标角注入方波，回 `BB:STEP ...` 确认；仅在已解锁且摇杆回中时生效 |
| `BB:STEP OFF` | 取消注入 |

### 摇杆帧两个槽位的含义变更

`bb_frame_t` 的 `accel_y` / `accel_z` 在**摇杆帧**里含义与数据帧不同，靠帧内 `reserved` 字节区分：

| `reserved` | 内容 | 说明 |
|---|---|---|
| `1` | **实际目标角** roll / pitch（×100） | 当前固件。就是送进控制器的设定值，阶跃分析直接用它 |
| `0` | 加计推算倾角 roll / pitch（×100） | 早期固件。仅供对比，**不能当设定值** |

上位机会自动识别；旧的 `.bin` 仍能分析，只是设定值要从摇杆换算（此时接收机微调未知，有恒定偏移）。

## 配置存储（内部 Flash 模拟 EEPROM）

参数（PID / 滤波 / 摇杆 / 油门 / 定高 / 降落 / 校准 / 开关共 82 项）存在 **STM32F405 内部 Flash 的最后两个
128KB 扇区**（0x080C0000 / 0x080E0000），跟黑匣子那颗 W25Q128 完全独立 —— 所以
`BB:ERASE` 全片擦除**不会**动配置。

### 生效模型：改 → 存 → 重启

```
python bb.py cfg set pid.roll_inner.kp 12     # 只改内存里的"待生效"值
python bb.py cfg save                         # 写进内部 Flash（~2ms）
python bb.py cfg reboot                       # 重启后生效
```

飞行代码只读**启动时的快照**，所以改参数绝不会让正在飞的飞机突然变性格。
`cfg list` 里被改过但没重启的项后面带 `*`。

> **唯一由固件自己写的参数：`alt.hover_throttle` / `alt.ref_throttle` / `alt.ref_pct`。**
> 每次 disarm（未解锁）时，如果学到的悬停油门变化超过 5 PWM，Logger 任务会写 Flash
> 并在串口回一行 `BB:HOVER SAVED 1700 @ 24% (was 1655 @ 20%)`；下次上电自动恢复。
>
> 后两个是**参考点**：`alt.ref_throttle` = 学习时的悬停油门、`alt.ref_pct` = 当时的电量。
> 只存绝对油门是不够的 —— 同一架机满电悬停 1500、快没电要 1700，换块满电电池上来
> 还按 1700 给油门就会一直往上冲。固件在**未解锁期间**按
> `基准 = ref_throttle − 2.5 × (当前电量 − ref_pct)` 折算，所以换电池后
> 第一次切定高就是准的。`ref_throttle` 出厂默认 537（远低于真实悬停油门），
> 表示"还没有参考点"，此时退回"只按绝对油门"的老行为。
>
> 想让它重新学：`python bb.py cfg set alt.hover_throttle 0 --save`。

### 手动模式的油门曲线（GUI「油门曲线」页签）

手动模式（HORIZON）的油门可以过一条**分段线性曲线**，让某个摇杆区间变得"最缓"：

```
摇杆 1000 ──────── x1 ──────── x2 ──────── 2000
输出   0 ─────────── y1 ─────── y2 ─────── 1.0        （输出比例 0..1）
        ↑ 这段斜率 = (y1-0)/(x1-1000)   ↑ 缓区 (y2-y1)/(x2-x1)   ↑ (1-y2)/(2000-x2)
```

参数（重启生效，存 EEPROM）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `thr.cv_x1` | 1500 | 缓区起点（摇杆值） |
| `thr.cv_y1` | 0.50 | 该点的输出比例 |
| `thr.cv_x2` | 1700 | 缓区终点（摇杆值） |
| `thr.cv_y2` | 0.70 | 该点的输出比例 |

- **默认值与直线完全重合**，所以不调就等于没开，手动手感不变；
- 实际油门 ≈ `比例 × 1000 × thr.scale × 4.2 ÷ (电量×thr.comp_a + thr.comp_b)`。
  `thr.scale=3`、电量 70% 时，比例 0.5 ≈ 1590 PWM（这台机的悬停点）；
- 想让悬停附近更细腻：把 `x1` 放到悬停杆位（约 1500）、`y1` 设成"悬停比例"，
  再把 `y2` 设得只比 `y1` 大一点点 —— 缓区斜率就压下去了（示例：(1500,0.50)(1700,0.545)
  时缓区 0.023%/100 计数，是 1700~2000 段 0.152%/100 的 **1/6**）；
- 参数写坏（`x2<=x1` 或 `y2<=y1`）时固件整体退回直线，不会锁死油门。

GUI 的「油门曲线」页签（在「参数」之后，**横轴=摇杆、纵轴=油门输出**）可以直接拖滑块看曲线实时变化，
点「写入参数表」→「保存到 Flash」→ 重启生效。

降落不是"目标 −3m 硬压"，而是一个按高度减速的剖面 + 触地确认：

| 离地 | 目标下降率 |
|---|---|
| 5 m | 2.0 m/s（受 `alt.rate_max` 上限） |
| 2 m | 1.6 m/s |
| 1 m | 0.8 m/s |
| 0.4 m | 0.32 m/s |
| ≤0.31 m | `alt.land_flare`（默认 0.25 m/s） |

- 基准油门用**学到的悬停油门**（和定高一致），修正量只负责"降多快"，所以满电/没电手感一样；
- **判据 0：加计冲击（最可靠）**：`|a| > 2.5 g` 连续 3 ms 即断电。
  实测触地冲击 2.84~15.8 g，而全飞行空中振动最大 1.66~1.99 g，门槛两边都有余量。
  这是唯一"直接测量碰地"的信号 —— 触地瞬间桨洗气流撞地把气压打成 +0.28 m/s 的
  假"上升"，垂速判据会被骗（26 日 21:47 那次因此弹了 3 秒），加计上的 4.19 g 尖峰骗不了。
  **不受气压门控影响**，5 ms 内断电，落地即停。
- **其余判据只用"与绝对高度无关"的动力学证据**（2026-10-26 重写，旧版用
  `高度<0.28m 且 |垂速|<0.25` 会跟 flare 的 0.25 m/s 目标打架，导致 10~20 cm 空中断电）：
  ① **垂速塌陷**：最近 400 ms 内垂速曾 < −0.15 m/s，而现在**最近 200 ms 平均垂速**
     |v| < 0.12 m/s —— 只有地面能让下降中的飞机把速度归零。用平均值不用瞬时值：
     贴地时融合垂速会抖 ±0.09，瞬时门限 0.08 只有 1σ，判据会闪烁（26 日 21:37 那次
     飞机已趴地，判据在成立/失效之间跳，油门在 1315/1563 之间来回变，磨了 1 秒才断电）；
  ② **贴地高度兜底**：估计高度 < 0.08 m **且** 平均垂速 < 0.12 m/s（必须垂速也停住才算）；
  ③ 判据**不依赖绝对高度**，所以落脚点比起飞点高/低都能在**离地 0 m** 处断电
     （用实测曲线模拟 1~4 m 落差，断电点都在离地 ±0.00 m）。只留一个极松的 8 m 门限，
     防止在巡航高度出现"垂速塌陷"这种离谱情况；
  ④ 气压被桨洗撞地扰动时（|Δ气压高度|/Δt > 6 m/s）**推迟**断电 400 ms —— 但推迟有上限：
     触地条件累计满足 800 ms 就强制断电，避免气压反复跳变导致桨在地面磨到超时；
  ⑤ 判到触地、但还在 200 ms 确认窗里时，**油门先压到悬停的 85%**
     （地面效应下这个油门刚好"贴住地面"）：否则这 0.2~0.3 秒油门还挂在
     1520~1560，多出来的推力会把飞机顶起来"弹一下"（实测 26 日 21:28 那次）；
  条件连续满足 200 ms 才断电，断电原因记在数据帧 `flags` bit3-5
  （1=贴地高度 2=垂速塌陷 3=超时 4=气压门控升级）；
- **超时兜底**：`alt.land_timeout`（默认 40 s，考虑落脚点更低时要多降一段时间）到点强制断电；
- 高度数据不可用时：按悬停油门的 85% 温和盲降，由超时收尾；
- 落地断电后，**拨到定高或手动就是重新起飞**（飞手的明确意图；arm 是独立通道，拨模式开关不会误碰）。
  不想再起飞就 disarm。

调参只看两个：

```bash
python bb.py cfg set alt.land_flare 0.25    # 接地下降率：小了磨蹭、大了砸脚架
python bb.py cfg set alt.land_timeout 20    # 超时断电
```

```bash
python bb.py cfg get pid.roll_outer.kp
python bb.py cfg set pid.roll_outer.kp 8 --save --reboot
python bb.py cfg hist 10              # 最近 10 次保存 + 相邻版本 diff
python bb.py cfg rollback 2 --reboot  # 回滚到"倒数第 3 条"并生效
python bb.py cfg raw --out rec.bin    # 最新记录的原始字节（离线解析用）
python bb.py cfg erase                # 擦掉两个 bank（未解锁 + 输入 yes）
python bb.py calib                    # 重新标定零偏（地面、静止 2 秒），写入 cal.* 参数
python bb.py cal                      # 只读：这次上电自标定的质量
```

### 注意

- **烧写要用 Erase Sectors**，Erase Full Chip 会把配置区一起清掉（现象：`cfg info` 里 `src=def`）。
- 解锁状态下 `save / rollback / erase / reboot` 一律被拒（`CFG:ERR armed`）；`set` 允许（只改内存）。
- 一次保存 ~2ms；每 128 次保存会触发一次 ~1s 的扇区擦除（整机停顿），只在地面发生。
- 详细参数表与判读见 [`docs/flash_eeprom_p2_params.md`](../docs/flash_eeprom_p2_params.md)，
  设计背景见 [`docs/flash_eeprom_design.md`](../docs/flash_eeprom_design.md)。

| 页 | 能做什么 |
|---|---|
| **参数** | 75 项一览（可搜索 / 只看改动），选中改值 → `应用`（只改内存）；`保存到 Flash`、`重启生效`、`重新载入`、`恢复默认`；脏项标黄 |
| **历史 / 回滚** | 最近 10 条保存记录及每版差异；`加载到内存`（不写盘）或 `回滚并保存`；擦除配置区 |
| **预设** | 列出 `presets/*.json`；选中即预览与飞机当前值的差异；`应用到飞机`（可勾选保存+重启）；从飞机导出 |
| **日志** | 所有命令与回包原文，出问题先看这里 |
| **黑匣子** | `刷新状态` / `扫描扇区` / `校准报告` / `擦除全片`；`倾倒` 三种范围：**最近 N 段飞行（默认 N=1）** 或 全部已记录；`分析这个文件` 把 `bb.py analyze` 的报告直接显示在窗口里，勾选“出图”可生成曲线图并一键打开；`导出 CSV…` 把数据存成逐帧表格（Excel/MATLAB 直接用）；**「减去 trim」** 把 `ctrl.roll_offset_deg` / `pitch_offset_deg` 当零点 |
| **校准** | `标定（静止 2 秒）` 让飞机重新测陀螺零偏 + 加计零偏，结果显示 6 个 `cal.*` 参数并标出标定质量 `std`；配合 `保存到 Flash` / `重启生效` 落盘。已解锁时会被拒绝 |

> **校准页怎么用（档 2：只标零偏）**：飞机放平别动 → 点「标定（静止 2 秒）」→
> 看 `std < 0.5 dps`（偏大说明当时被碰过）→「保存到 Flash」→「重启生效」。
> 上电时若 `cal.*` 有一项非 0，就直接用存下来的零偏（**不再要求上电后静止**）；
> 全 0 时退回原来的 1 秒自标定，行为与以前完全一致。
> 参数里不带 `*` 表示已生效，带 `*` 表示改过还没重启。
> 命令行等价：`python bb.py calib`（标定并写参数），`python bb.py cal`（只读当前质量）。

> **“最近 N 段飞行”怎么做到只传这几段的**：先 `BB:SCAN` 拿扇区索引，再从最新扇区
> 往前按 64 个扇区一块下发 `BB:DUMP:<start>:<count>`。每次解锁都会切到新扇区并把
> 帧序号归零，所以某块里一旦出现"含 seq 1..8 **数据帧**的扇区"，那就是一段飞行的起点。
>
> ⚠ 两个坑（都已在代码里处理，改这块前务必看一眼）：
> 1. **不能读"扇区第一个帧"的 seq**：实测每个扇区第 0 个槽位几乎总是诊断帧/摇杆帧
>    （type 2/3），它们那个 seq 槽位存的是 conf/period（会读出 2563 这种值）。
>    必须筛 `type == 1` 的数据帧。
> 2. **16 位序号会回绕**（每 65536 帧 ≈ 65 秒），回绕也会看到 seq 归零。判断"前一扇区
>    末帧 seq ≥ 60000"就说明是回绕，不是新的一段，要继续往前倒。
>
> 实测：一份 130 个扇区的真实镜像里有两段飞行（3 号扇区和 101 号扇区各一段），
> 取 1 段只传 64 个扇区、落盘 32 个扇区（3.7 秒）；取 2 段才把两段都拿全（15.3 秒）。
> 想多拿几段就把"最近 N 段"调大，比 `全部已记录` 快得多。
>
> 黑匣子页只在切过去时自动查一次状态；倾倒和擦除都要求未解锁，擦除约 200 秒，
> 中间每 3 秒轮询一次进度，可以点“停止等待”（擦除仍在飞控后台继续）。
> 离线分析只读本地 `.bin`，**不占串口**，所以没连飞机也能用。

几个实现约定（改了别踩）：

- **串口默认值跳过 COM1**：COM1 通常是主板自带的 9 针口/蓝牙串口，飞控插的是 USB 转串口
  （一般 COM3 以上）。`bb_serial.pick_default_port()` 会被 GUI 和 `bb.py` 共用：
  有多路串口时自动选第一个非 COM1 的，只有 COM1 才退回 COM1。
- **串口只归 worker 线程所有**。GUI 线程绝不直接读写 —— USART3 上文本和二进制混跑，
  两边同时读会抢字节。所有操作排队给唯一的工作线程，忙时按钮自动禁用。
- 重启（`CFG:REBOOT`）之后会自动 `关闭 → 重开` 串口并刷新；失败时提示手动点“连接”。
- `导出 CSV` 用的是 `bb_analyze` 的 `--csv`，导出的是**它认定的最新一段连续数据**
  （倾倒时选 N=1 就正好是全部内容；选多段时 CSV 只含最新那段）。
- **「减去 trim」默认不勾**（= 保留 offset，曲线在摇杆回中时停在 +offset）。
  勾上后会把**实测姿态和设定值一起**减掉框里的两个角度，让"摇杆回中 = 0°"；
  两个框在连上飞机后会自动填成 `ctrl.roll_offset_deg` / `ctrl.pitch_offset_deg`
  （点「从飞机读」可刷新，也能直接改）。命令行等价写法：
  `python bb.py analyze f.bin --trim-roll 1.0 --trim-pitch 0.36`。
- 快捷键：`F5` 刷新、`Ctrl+S` 保存、`Ctrl+R` 重启。

## 分析报告怎么读

`bb.py analyze` 会针对**左偏问题**给出判读，重点是这几项：

| 观察项 | 含义 | 指向 |
|---|---|---|
| `roll 漂移率` 大且与时间强相关 | 越飞越歪（发散） | 姿态**基准在移动**，不是固定偏置 |
| `roll 漂移率` 小但仍感觉偏 | 固定角度偏置 | 基准偏了恒定角度 / 机械问题 |
| `陀螺 Y 低频变化` 大 | 零偏在飞行中漂 | 零偏 × 时间 = 姿态误差 |
| `accel_confidence` 掉下来 | 重力修正被关掉 | 那段时间纯靠陀螺积分，零偏直接累积 |
| `\|\|a\|-1g\|` 长期偏大 | 振动污染重力参考 | 减震 / 改置信度判据 |
| `解算周期` 偏离 1000µs | 写死 dt 是错的 | 姿态等效增益与重力修正强度都被改变 |
| `左-右` 差动持续偏一侧 | 控制器在单向用力 | 配合上面的项判断是"基准偏"还是"机械偏" |

### 高度估计（报告第 7 节 / 曲线图 8~9 格 / CSV 最后 9 列）

有高度帧（type=4）时，报告会多出一节；`--plot` 的图会多两格（气压+融合高度、垂速+定高修正量）；
`--csv` 会多出 `baro_m / alt_m / vvel_mps / innov_m / bias_mps2 / baro_dt_ms / thr_corr / press_hpa / alt_ok`。

| 观察项 | 含义 / 判读 |
|---|---|
| `baro_ok 占比` < 100% | 有段时间气压不可用（这时定高会被禁止，`alt_ok=0`） |
| `气压更新间隔` 明显 > 50ms | I2C 慢 / 任务被抢占；`baro_dt` 同时是"样本有多老"的度量 |
| `[!] N% 相邻气压样本完全相同` | 读取周期短于 BMP280 转换时间。固件已改成 50ms 读取 + IIR 系数 2，正常情况下应降到 0 |
| `融合-气压 平均|差|` | 滤波器的滞后量。**远大于气压抖动**说明增益太小（跟不动） |
| `创新 innov` 平均/95% | 修正强度。正常应与气压抖动同量级；被限幅说明有坏样本 |
| `加计偏置` 漂到很大（>0.1） | 加计刻度/零偏有问题，或长期没被气压纠正 |
| `定高修正量` 一直为 0 | 定高没开（`flags` bit1=0）或高度数据无效（`alt_ok=0`） |
| `定高修正量` 中位长期偏离 0（>200） | **基准油门与真实悬停油门不匹配**。看下一行 `基准油门`：没学到就是学习没生效；学到了还偏就是 `thr.tho_h/tho_l` 与机体不符 |
| `基准油门`（学到的悬停油门） | 悬停油门学习的输出。悬停时它应 ≈ 四路电机均值，此时修正量≈0 |
| `[!] N% 相邻气压样本完全相同` | 读取周期短于 BMP280 转换时间（×16 约 40ms，读的是 20ms）→ 有效更新率减半且样本偏老 |

> 时间轴 `t_s` 现在按固件的 1kHz 序号累加（高度帧/摇杆帧不占 1ms），
> 不再是"槽位号/1000"——后者会把整条轴拉长约 8%。
